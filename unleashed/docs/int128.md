# Int128 / UInt128

Native 128-bit signed (`Int128`) and unsigned (`UInt128`) integer types that behave like any other ordinal - the same way `Int64` / `QWord` extend the 32-bit types. Literals, arithmetic, comparisons, `div` / `mod`, shifts, bitwise ops, `inc` / `dec` / `succ` / `pred`, `abs` / `odd` / `sqr`, `for` loops, `case`, range / overflow checking, `Str` / `Val`, and `Write` / `Read` all work.

The types are always available on 64-bit ALU targets. Integer literals wider than 64 bits are gated by modeswitch `int128`, enabled by default in `{$mode unleashed}`.

```pas
{$mode unleashed}
var
  a: Int128;
  u: UInt128;
begin
  a := 170141183460469231731687303715884105727;   // high(Int128) = 2^127 - 1
  u := 340282366920938463463374607431768211455;   // high(UInt128) = 2^128 - 1
  writeln(a);
  writeln(u);
end.
```

## Types and literals

| Type      | Bits | Range                                          |
|-----------|------|------------------------------------------------|
| `Int128`  | 128  | -2^127 .. 2^127 - 1                             |
| `UInt128` | 128  | 0 .. 2^128 - 1                                  |

`low(Int128)`, `high(Int128)`, `low(UInt128)`, `high(UInt128)` return the bounds as 128-bit constants.

Only the decimal (and modeswitch-gated wider) literal forms carry the full 128-bit value. Outside `{$mode unleashed}` (or without `{$modeswitch int128}`) a literal that overflows `Int64` / `QWord` falls back to the historical real-constant behavior, so existing code is unaffected. The `Int128` / `UInt128` type names themselves stay usable in `objfpc` / `delphi` - only the oversized literal needs the switch:

```pas
{$mode objfpc}
{$modeswitch int128}
var a: Int128;
begin
  a := 100000000000000000000000000000000000000;   // 1e38, needs the switch
end.
```

## Arithmetic

`+`, `-`, `*`, `div`, `mod`, unary `-` operate on the full 128-bit value with two's-complement wraparound (no implicit widening to a bigger type - there is none).

```pas
var a, b, c: Int128;
a := 10000000000000000000;        // 1e19, past high(Int64)
b := 10000000000000000000;
c := a * b;                       // 1e38, exact in 128 bits
```

`div` truncates toward zero; the sign of `mod` follows the dividend, matching `Int64`:

```pas
a := -100;
writeln(a div 7);                 // -14
writeln(a mod 7);                 // -2
```

## Shifts

`shl` / `shr` shift across the full 128-bit payload; the shift count is taken mod 128. `shr` is a logical shift (zero fill) for both `Int128` and `UInt128`, the same as `shr` on the 64-bit types.

```pas
var u: UInt128;
u := 1;
u := u shl 100;                   // 2^100 = 1267650600228229401496703205376
writeln(u shr 100);               // 1
```

## Bitwise

`and`, `or`, `xor`, `not` operate on the 128-bit two's-complement bit pattern.

```pas
u := 18446744073709551615;        // low 64 bits set (2^64 - 1)
v := u shl 64;                    // high 64 bits set
writeln(u or v);                  // 2^128 - 1 (all bits)
writeln(u and v);                 // 0 (disjoint)
writeln(not UInt128(0));          // 2^128 - 1
```

## Comparisons

`=`, `<>`, `<`, `<=`, `>`, `>=` compare `Int128` as signed and `UInt128` as unsigned, so the same bit pattern orders differently under the two types (e.g. all-bits-set is `-1` as `Int128` but `2^128 - 1` as `UInt128`).

## Conversions

Widening from any narrower integer to `Int128` / `UInt128` is implicit. Narrowing back (`Int128` -> `Int64`, etc.) follows the usual truncation / range-check rules. `Int128` / `UInt128` convert to `Double` (with the expected precision loss for magnitudes beyond 53 bits).

```pas
var i: Int64; a: Int128; d: Double;
i := high(Int64);
a := i;                           // implicit widen
a := a + a;
d := a;                           // 1.8446744073709552E19
```

## Str / Val / Write / Read

`Str`, `Val`, `Write(ln)`, and `Read(ln)` handle both types, including the full decimal range and signs.

```pas
var a: Int128; s: string; code: Integer;
a := 123456789012345678901234567890;
Str(a, s);                        // '123456789012345678901234567890'
Val('-99999999999999999999999999999', a, code);   // code = 0
```

`Val` reports the 1-based position of the first offending character in `code`, as for the other integer types.

## for, case, inc / dec / succ / pred

A 128-bit value does not fit a register, so these constructs lower to forms that reach the runtime helpers: a `for` loop with a 128-bit counter becomes a `while` loop, an ordinal `case` on a 128-bit selector becomes an if-else chain, and `inc` / `dec` / `succ` / `pred` express as an add / subtract. The surface behavior is identical to the smaller ordinals.

```pas
for a := high(Int128) - 2 to high(Int128) do
  inc(count);                     // runs 3 times

case a of
  1:                     s := 'one';
  100000000000000000000: s := 'match';
else
  s := 'none';
end;
```

## abs / odd / sqr

Provided for both types. `abs(low(Int128))` wraps (its magnitude has no positive 128-bit representation), matching the other signed ordinals.

## Range and overflow checking

`-Cr` (range checks) and `-Co` (overflow checks) are honored: an out-of-range narrowing raises a range error, and an operation that overflows 128 bits under `-Co` raises `EIntOverflow`. Without the switches, arithmetic wraps silently as above.

## Hex literals

A hex literal that fits in `Int64` is parsed as a signed `Int64` and then sign-extended when it lands in a 128-bit context - the same rule the language already applies elsewhere. So in a 128-bit slot `$ffffffffffffffff` is `-1` (all 128 bits set), not `2^64 - 1`:

```pas
u := $ffffffffffffffff;           // 2^128 - 1 (sign-extended -1), NOT 2^64 - 1
u := 18446744073709551615;        // 2^64 - 1 (use decimal for the low-64 mask)
```

## Codegen and ABI

128-bit operations lower to `fpc_*_int128` runtime helpers (the same model gcc uses with `__divti3` and friends), with the fast in-place paths handled inline. A 128-bit value is passed and returned by reference, like a 16-byte record. Constant folding uses the compiler's arbitrary-precision integer, widened to hold the full 128-bit payload, so compile-time expressions match runtime results. On targets without a 64-bit ALU the widening and the range check go word by word rather than through a 64-bit register, so they work there too.

## Platform scope

`Int128` / `UInt128` work on x86_64 (win64 / linux64) and on i386, both fully exercised: arithmetic, `div` / `mod`, shifts, comparisons, conversions, `Str` / `Val`, `for` / `case`, and range (`-Cr`) / overflow (`-Co`) checking. The design is not tied to a 64-bit ALU - the helpers ride on the same multi-word `qword` support `Int64` uses on smaller targets - so it extends to other CPUs as their parameter ABI is wired up.
